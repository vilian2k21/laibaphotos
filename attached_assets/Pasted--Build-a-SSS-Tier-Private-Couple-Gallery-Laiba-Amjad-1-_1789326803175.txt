# 3. TECHNOLOGY STACK

Use the best practical technologies for a production-quality Railway deployment. Do not use unnecessary technologies just to make the stack sound impressive.

## Frontend

* React with TypeScript.
* Vite.
* Tailwind CSS.
* Framer Motion for smooth animations.
* A polished component system with consistent spacing, typography, and responsive behavior.
* Lucide React or another high-quality icon library.
* Modern image and video loading techniques.

## Backend

Use Node.js with TypeScript and Express, or another well-supported production-ready Node.js framework.

The backend must handle:

* Authentication.
* Media metadata.
* Gallery browsing.
* Uploads and imports.
* Albums.
* Favorites.
* Search.
* Secure media access.
* Database operations.
* Health checks.
* Production error handling.

## Database

Use PostgreSQL for production, preferably through Railway PostgreSQL or Supabase PostgreSQL.

Use Prisma ORM or Drizzle ORM with proper migrations.

Do not use SQLite as the primary production database if the app is expected to scale or run reliably across Railway deployments.

## Media storage

Design the storage layer properly.

The application must not rely on temporary server filesystem storage for permanent media.

Support a persistent storage provider such as:

* Cloudflare R2.
* Amazon S3-compatible storage.
* Supabase Storage.
* Another reliable object-storage provider.

The storage provider must be configurable through environment variables.

If Railway volume storage is used, explain its limitations and configure it correctly for persistent media. Do not assume the container filesystem is permanent.

## Deployment

The app must be compatible with:

* Railway.com.
* Railway PostgreSQL.
* Railway environment variables.
* Production builds.
* A single deployable full-stack service where practical.
* Separate frontend/backend services only if there is a clear technical advantage.

Provide complete deployment instructions and production configuration.
